## How to actually apply these (read this before pasting)

Two different fields, two different persistence stories:

- **`headline`** comes from `player_profiles.taste_fingerprint.summary`
  (`buildReadModel.ts:766`). Editing that JSON field is durable — it survives republish,
  and only a fingerprint regeneration would overwrite it.
- **`signatureSuperlative` / `superlatives`** are **regenerated by the LLM on every
  publish** (`narrative-player-superlatives`, `buildReadModel.ts:568`). Hand-written
  awards pasted into `read_model.json` get blown away on the next publish. Two options:
  1. add a per-player override table (or a `player_profiles` column) that
     `buildReadModel` prefers over the LLM output, or
  2. feed the personal-color notes into the superlatives task as an extra input so the
     model writes *around* them (the task currently only sees fingerprint + stats —
     `player_profiles.notes` is **not** wired into it).

Option 1 is the smaller change and the only one that makes the text stable.
