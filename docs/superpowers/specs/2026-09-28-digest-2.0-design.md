# Digest 2.0 — design spec

**Date:** 2026-09-28
**Status:** Draft for review (design-only; no implementation until approved and planned)
**Companion:** content model lives in `~/Documents/2026-09-28-digest-redesign-blueprint-v2.md` (the three-bucket model + the locked 10-visual stats default). This spec is the *engineering* half: how to build that model as a parallel system without endangering the live digest.

---

## 1. Goal

Ship a simpler, more visual round digest that folds in the Boarz Stats Explorer, **built as a parallel "digest 2.0" system** that cannot break the live ("1.0") digest. Live 1.0 keeps running untouched; 2.0 is opt-in per league; 1.0 is retired only after 2.0 proves out.

## 2. Non-goals / hard constraints

- **Do not mutate the live digest's write path.** Specifically: never widen or rebuild the shared `digest_sections.kind` CHECK or the `digest_drafts` columns; never add a second writer to `digest_jobs` / `digest_sends`; never add a second writer to the `digests/` volume's `/d/<slug>/` or `/_media/` namespaces; never broaden the Access-less `Caddyfile.digest` proxy beyond its current `/api/p/*`.
- **Not in scope (parked):** the "live/interactive digest as part of the game" (theme voting, live chat analysis, listening room). Separate future effort.
- **Not in scope:** the season-finale "Wrapped" digest (2.0 is per-round; Wrapped is a later season-scoped variant).

## 3. The content model (summary — full detail in the blueprint)

Every 2.0 digest is assembled from three kinds of block:

1. **Auto sections** — generated every round with no manual work:
   - *Story (LLM):* Podium, Villain, Chat notes, The Regulars, Coinage.
   - *Structural/deterministic:* Standings chart, Next-round teaser, Album podium, Tastemaker, Guesser leaderboard, Reel.
2. **One consolidated Stats/Graph section** — fed read-only by the Boarz Stats Explorer. Locked default = **10 visuals**: Leaderboard Race · Top Songs · Top Artists · Vote Heatmap · Voter Generosity · Playlist Position Bias · Contrarian Score · Talkativeness · Roast Report · Daily Activity (chat vs ML). Everything else in the explorer is builder-only.
3. **One-off builder library** — every section *not* in the auto set (the un-ticked LLM sections: Flow, Consensus, Liner quotes, Phrase of the round, Chat Lab; the un-ticked deterministic: Sound profile, Submission race, Language of the room, Round signals, Season callbacks, Stat strip, Player Cards; and the non-default explorer visuals). Preserved, never deleted; dropped into any digest on demand through a **digest builder** UI.

## 4. Isolation strategy — Approach A (fork, share the read-side)

Chosen over (B) flag-in-shared-pipeline and (C) shared-core-refactor because both keep the live digest in the blast radius; A makes breaking 1.0 structurally impossible. The cost — duplicated pipeline/route code that can drift — is acceptable and temporary (1.0 is retired after cutover).

### 4.1 Fork boundary

| Concern | Live 1.0 | Digest 2.0 | Rule |
|---|---|---|---|
| League DB (`data/league.db`) | read+write | **read-only for game data** | 2.0 reads rounds/votes/chat/etc.; writes ONLY to its own `digest2_*` tables |
| Draft/section schema | `digest_drafts`, `digest_sections` (CHECK) | **new** `digest2_drafts`, `digest2_sections` (no CHECK — 2.0 owns its kinds) | never touch 1.0's tables or its boot migrations |
| Job queue | `digest_jobs` | **new** `digest2_jobs` | separate queue → no double-claim |
| Send idempotency | `digest_sends` | **new** `digest2_sends` | separate log → no double-send |
| Share slugs / output | `digest_shares` → `/d/<slug>/` | **new** `digest2_shares` → `/d2/<slug>/` | distinct path prefix on shared volume |
| Media | `/_media/*` | **shared, read-only reuse** | 2.0 references existing media; must not overwrite |
| Boarz stats compute | — | **shared, read-only import** of `lib/server/boarzStats/*` | embed, never fork the compute |
| Hostnames | `config/urls.ts` | **shared** | reuse `appBaseUrl()`/`digestBaseUrl()`; no hardcoded hosts (guard test) |
| Pipeline/runner/prompts | `lib/digest/*`, `llm.ts` | **forked copy** → `lib/digest2/*` | the whole point of 2.0 |
| Routes | `digest/[roundId]`, `api/digest/*` | **forked** → `digest2/[roundId]`, `api/digest2/*` | |
| Section components + css | `lib/digest/*.svelte` | **forked/adapted** copies | |
| MCP tools | `generate_digest`, … | **add** `generate_digest_v2` → `/api/digest2/*` | additive |
| Auto-runner | `startDigestRunner()` (60s) | **own** `startDigest2Runner()` (own `DIGEST2_RUNNER_POLL_MS`), its own deps pointing at `/api/digest2/*` | never reuse 1.0 `buildRunnerDeps` (it drives live routes) |

## 5. Architecture

### 5.1 Data model (new tables, added via `schema.ts` `CREATE TABLE IF NOT EXISTS`)

- **`digest2_drafts`** — `round_id`, `id`, `generated_at`, `finalized_at`, `layout_json` (the ordered block list — the assembled digest: which blocks, order, which graph visuals selected), `stats_params_json` (season-to-date snapshot params), `llm_cost_usd`, `run_id`.
- **`digest2_sections`** — `id`, `draft_id` (FK CASCADE), `position`, `kind` (**plain TEXT, no CHECK** — 2.0 defines its own kinds incl. `graphs`, `builder-*`), `source` (`'auto' | 'oneoff'`), `state` (`default|excluded|locked`), `content_json`, `variant`.
- **`digest2_jobs`**, **`digest2_sends`**, **`digest2_shares`** — mirror the 1.0 queue/send/slug tables, separate namespace.

New tables are additive `CREATE TABLE IF NOT EXISTS` — they do not touch the destructive rebuild logic in `client.ts`, which only fires on the 1.0 tables' CHECK.

### 5.2 The Stats/Graph section

- A `digest2_sections` row of kind `graphs`. Its `content_json` = the ordered list of selected explorer visual ids (default = the 10) + the season snapshot params.
- Renders by calling `buildSnapshotCached(...)` from `lib/server/boarzStats/data.ts` **read-only** (it already opens `league.db` `readonly:true`), then mounting the corresponding per-visual pieces of the existing `boarzStats/*.svelte` tab components. **Do not fork the compute**; if a visual isn't independently mountable, extract a thin read-only render prop in the shared component rather than copying its math.
- Scope: renders **season-to-date through the current round** (the explorer is season-scoped; 2.0 passes the round as the upper bound).

### 5.3 The digest builder UI (the crux)

New route `digest2/[roundId]` (the editor) with a **builder panel**:
- **Assembled column** — the current digest: auto blocks pre-populated, reorderable, each removable/lockable.
- **Library column** — all one-off blocks, grouped (Story · Deterministic · Extra graph visuals). Add → inserts a `source:'oneoff'` section; LLM one-offs generate on add, deterministic/graph pull data on add.
- Persist the assembled order to `digest2_drafts.layout_json` + rows in `digest2_sections`.
- The builder is a pure assembly/CRUD surface over 2.0 tables; generation reuses the forked `lib/digest2` pipeline.

### 5.4 Pipeline / runner

- Fork `pipeline.ts`, `runner.ts`, `runnerLoop.ts`, `sectionState.ts`, `approvals.ts`, `jobs.ts`, `schedule.ts`, and the needed generation functions from `llm.ts` into `lib/digest2/`.
- `startDigest2Runner()` mounted in `hooks.server.ts` alongside the existing one, with its **own** deps calling `/api/digest2/{draft,render,finalize}` and its own poll env var.
- Approval + send lifecycle forked onto `digest2_jobs`/`digest2_sends`; approval/review URLs via `appBaseUrl()`.

### 5.5 Serving

- Render 2.0 artifacts to `digests/d2/<slug>/` (new prefix on the shared volume). Add a **`/d2/*`** block to `Caddyfile.digest` mirroring `/d/*` (static, cached). Reuse `/_media/*` read-only. **Do not** touch the `/api/p/*` proxy or add any app proxy to that Access-less host.

### 5.6 MCP + scheduling

- Add `generate_digest_v2` (and, if needed, `check_digest2_readiness`) to `mcp-server/src/tools/digest.ts` as thin HTTP proxies to `/api/digest2/*`. Additive registration.
- Add a `mlb-digest2-*` host timer only if 2.0 needs one; the in-process `startDigest2Runner()` is the primary driver.

### 5.7 Per-league opt-in / cutover

- A league setting (e.g. `settings.digest_engine_<leagueSlug>` = `v1|v2`, default `v1`) selects which engine auto-runs and which editor the `/content` index links to. 1.0 stays default. Flip a league to `v2` to trial; retire 1.0 per league once satisfied.

## 6. Testing strategy

- **Isolation guard tests (highest priority):** a test asserting 2.0 writes touch only `digest2_*` tables; a test asserting no 2.0 code path enqueues to `digest_jobs`/`digest_sends`; reuse/extend `hostLiterals.test.ts` so 2.0 adds no hardcoded hosts.
- **Schema safety:** a test that opening the DB with the 2.0 tables present does not alter the 1.0 `digest_sections.kind` CHECK or `digest_drafts` shape.
- **Stats embed:** snapshot test that the graph section renders the 10 defaults from a fixture DB read-only.
- **Builder:** assemble → persist `layout_json` → reload round-trips; add/remove/reorder one-offs.
- **Send idempotency:** 2.0 `digest2_sends` claim/mark path never double-sends; and the 1.0 and 2.0 runners can both poll without cross-claiming (separate queues).
- Follow repo convention: run **gitnexus impact analysis** before editing any shared symbol (esp. anything in `boarzStats/` or `config/urls.ts`), and detect-changes before commits.

## 7. Risks & mitigations (from the coupling map)

| Risk | Mitigation |
|---|---|
| Boot migrations rebuild 1.0 tables destructively if CHECK is touched | 2.0 never touches 1.0 tables; new tables only |
| Two runners → double WhatsApp sends | separate `digest2_jobs`/`digest2_sends`; separate deps |
| Second writer clobbers `/d/<slug>/` or `/_media/` | 2.0 writes only `/d2/`; media read-only |
| Access-less host publishes admin app | never widen the `/api/p/*`-only proxy |
| Forked `buildRunnerDeps` drives LIVE routes | 2.0 builds its own deps → `/api/digest2/*` |
| Duplicated `llm.ts` logic drifts from 1.0 | acceptable while both live; retire 1.0 after cutover; share read-only helpers where safe |

## 8. Decisions & open questions

**Decided (2026-09-28):**
- **Builder scope:** *auto-set first.* Phase ① ships the fixed auto digest (story sections + 10-visual graph section) with no builder; the one-off library/builder is Phase ④. Fastest path to a lookable 2.0.
- **Cutover unit:** *per-league `v1|v2` flag* (§5.7). Trial by flipping one quiet league to `v2`, leave the rest on `v1`.

**Still open (resolve during planning):**
1. **How much of `llm.ts` to fork** vs. import read-only helpers — per-function pass during planning (~62k lines; fork only the generation entry points the auto set uses).
2. **Graph-visual mountability:** confirm each of the 10 default visuals renders standalone from `boarzStats/*` without copying compute; list any needing a thin extraction.
3. **Approval/HiL:** does 2.0 reuse the same ntfy approval UX and the `mlb-hil-ledes` ledes flow, or a simplified one?
