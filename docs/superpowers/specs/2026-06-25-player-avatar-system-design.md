# Player Avatar System — Design Spec

**Date:** 2026-06-25  
**Status:** Approved  
**Roadmap item:** `bside-llm-avatars`

---

## Overview

Per-player illustrated avatars generated by OpenRouter image models, stored in Cloudflare R2, displayed on the b-side member grid, player research tab, and digest season standings. Two avatar tiers: a **base avatar** (operator-managed, generated once from player traits or uploaded manually) and a **themed avatar** (auto-generated at round-start, styled to the round's theme). A graceful fallback chain ensures the initials circle always appears when no avatar exists.

## Data Model

### New table: `player_avatars`

```sql
CREATE TABLE IF NOT EXISTS player_avatars (
  player_id             INTEGER PRIMARY KEY REFERENCES players(id),
  base_r2_key           TEXT,        -- e.g. "42/base.png"
  themed_r2_key         TEXT,        -- e.g. "42/themed.png"
  themed_round_id       INTEGER,     -- which round's theme the themed avatar reflects
  base_generated_at     TEXT,
  themed_generated_at   TEXT,
  base_source           TEXT CHECK(base_source IN ('generated','uploaded')) DEFAULT 'generated'
);
```

### New columns on `player_profiles`

```sql
ALTER TABLE player_profiles ADD COLUMN avatar_gender TEXT;   -- 'male'|'female'|'nonbinary'
ALTER TABLE player_profiles ADD COLUMN avatar_hair   TEXT;   -- freeform: "curly red", "bald"
ALTER TABLE player_profiles ADD COLUMN avatar_height TEXT;   -- 'petite'|'short'|'average'|'tall'|'very tall'
ALTER TABLE player_profiles ADD COLUMN avatar_build  TEXT;   -- 'lanky'|'medium'|'athletic'|'thick'
ALTER TABLE player_profiles ADD COLUMN avatar_style  TEXT;   -- 'average'|'skater'|'preppy'|'formal'|'jock'|'punk'|'bohemian'
ALTER TABLE player_profiles ADD COLUMN avatar_trait  TEXT;   -- freeform: "big beard, glasses, always smiling"
```

### New global setting

Key: `avatar_age_shift`  
Type: integer  
Default: `0`  
Range: −20 to +20  
Meaning: added to each player's age before building the image prompt. Negative = render younger.

> **Test config:** set `avatar_age_shift = -15`, leave player ages unset (fallback = 40). Effective prompt age = 25.

### `ai_models` table — new column

```sql
ALTER TABLE ai_models ADD COLUMN cap_image_gen INTEGER NOT NULL DEFAULT 0;
```

Distinct from `cap_vision` (which means the model can *receive* images as input). `cap_image_gen = 1` means the model can *generate* images via `modalities: ["image","text"]`.

### Model setting

Settings key: `avatar_image_model`  
Env fallback: `OPENROUTER_AVATAR_IMAGE_MODEL`  
Resolved by: new `modelForSection('avatar', db)` bucket

## Age Handling

```
effective_age = (player.age ?? 40) + avatar_age_shift
effective_age = clamp(effective_age, 5, 95)
```

- Players with no age set use **40** as the fallback.
- Shift is the global `avatar_age_shift` setting.
- Result is clamped to [5, 95] before being written into the prompt.

## Prompt Construction

### Base avatar prompt

```
Cartoon portrait illustration of a [gender] person, approximately [effective_age] years old,
[height] height, [build] build, [style] style, [hair] hair.
Key trait: [trait].
Square format, warm friendly illustration style, no text, no background clutter.
```

Fields omitted from the prompt when blank: `hair`, `trait`. `gender` and `style` are required to enable the Generate button.

### Themed avatar prompt (base + layer)

```
[base prompt as above]

Style them for this round's theme: "[theme title]" — [theme description].
Keep their core appearance but dress, pose, and surround them to reflect the theme.
```

## Generation Pipeline

### Base avatar — on demand

```
POST /api/players/[id]/avatar/generate-base
  → resolve player traits + effective_age
  → validate: gender + style required, else 400
  → callOpenRouterImage(prompt, model, { aspect_ratio: "1:1" })
  → on success: upload PNG bytes to R2 key "{playerId}/base.png"
  → upsert player_avatars: base_r2_key, base_generated_at, base_source='generated'
  → return { url: "/api/avatars/{id}/base" }
```

### Themed avatar batch — round start trigger

```
POST /api/avatars/generate-themed  { roundId }
  → fetch round (title, description)
  → fetch all players with avatar_gender IS NOT NULL
  → fan out: Promise.all per player → callOpenRouterImage(themed_prompt)
  → per-player: upload to R2 key "{playerId}/themed.png"
  → upsert player_avatars: themed_r2_key, themed_round_id, themed_generated_at
  → per-player failures are isolated — log error, continue batch
  → return { generated: N, failed: M }
```

### Manual upload

```
POST /api/players/[id]/avatar/upload   (multipart, field: "avatar", max 5MB, PNG/JPG)
  → validate file type + size
  → upload to R2 key "{playerId}/base.png"
  → upsert player_avatars: base_r2_key, base_generated_at, base_source='uploaded'
  → return { url: "/api/avatars/{id}/base" }
```

### Serve route

```
GET /api/avatars/[playerId]/[type]   (type = "base" | "themed")
  → look up r2_key from player_avatars
  → if no key: 404
  → fetch from R2 REST API with Bearer token
  → stream response with Content-Type: image/png, Cache-Control: max-age=3600
```

### OpenRouter image call (new helper: `callOpenRouterImage`)

Mirrors the `generateImage` function from `ml_companion/openrouter-round-story`:

```typescript
body = {
  model,
  messages: [{ role: 'user', content: prompt }],
  modalities: ['image', 'text'],
  image_config: { aspect_ratio: '1:1' }
}
// endpoint: https://openrouter.ai/api/v1/chat/completions
// response: choices[0].message.images[0].image_url.url
// handles both URL and data:image/... base64
```

## Settings UI

### Music League setup tab — global

**Avatar Age Shift** — number input, range −20..+20, default 0, label: *"Shift all avatar ages by N years (negative = younger)"*. Lives in the existing global settings panel on the Music League tab.

### Player editor — new "Avatar" section

Per-player collapsible section at the bottom of each player edit card:

| Field | Control | Options |
|---|---|---|
| Style | Segmented pill | `average` `skater` `preppy` `formal` `jock` `punk` `bohemian` |
| Gender | 3-way pill | `male` `female` `nonbinary` |
| Height | Dropdown | `petite` `short` `average` `tall` `very tall` |
| Build | Dropdown | `lanky` `medium` `athletic` `thick` |
| Hair | Text input | freeform |
| Freeform trait | Text input | freeform |
| Base avatar | Image preview + `Upload` button + `Generate` button | Generate disabled until gender + style set |

Generate button shows a spinner while the request is in flight. Upload triggers a hidden `<input type="file" accept="image/png,image/jpeg">`.

### Backup checkboxes on generation modals

Both digest generation modal and b-side generation modal get an identical unchecked checkbox:

```
☐ Regenerate themed avatars for this round
```

When checked, the modal's submit handler calls `POST /api/avatars/generate-themed { roundId }` before/after the main generation job.

## Avatar Component Changes

`bside/src/lib/atoms/Avatar.svelte` gains an optional `src` prop:

```svelte
interface Props {
  hue: string;
  initials: string;
  size?: 'sm' | 'md' | 'lg';
  src?: string | null;   // new — served URL
}
```

When `src` is set, renders an `<img>` instead of the initials div. Falls back to initials on image load error.

**Fallback chain (applied at read-model build time and in the component):**

```
themed_r2_key populated → src = "/api/avatars/{id}/themed"
else base_r2_key populated → src = "/api/avatars/{id}/base"
else → src = null (initials circle)
```

## Error Handling

| Scenario | Behavior |
|---|---|
| OpenRouter returns no image | Toast error in Settings; no DB write; existing avatar unchanged |
| R2 upload fails | Same — toast, no write; in themed batch: log + continue, other players unaffected |
| Upload file > 5MB | Rejected client-side before server hit; inline error message |
| Generate clicked without gender + style | Button disabled; tooltip: "Set gender and style first" |
| Serve key not found in DB | 404 |
| Image load error in component | Falls back to initials circle silently |
| `age + shift` out of [5, 95] | Clamped in prompt builder; no error |

### Task 2 — Backend: image helper + serve endpoint

Files: `ui/src/lib/server/openrouter.ts` (new helper), `ui/src/routes/api/avatars/[playerId]/[type]/+server.ts` (new)

1. Add `callOpenRouterImage(prompt, model, opts)` helper — mirrors existing `generateImage` in `ml_companion/openrouter-round-story`. Handles both URL and `data:image/...` base64 responses. Throws on missing image.

3. Create `GET /api/avatars/[playerId]/[type]` serve route — looks up `r2_key` from `player_avatars`, fetches from R2 REST API with Bearer token, streams `image/png` with `Cache-Control: max-age=3600`. Returns 404 when key absent.

### Task 3 — Backend: generate-base + upload endpoints

Files: `ui/src/routes/api/players/[id]/avatar/generate-base/+server.ts`, `ui/src/routes/api/players/[id]/avatar/upload/+server.ts`

1. Build `buildBasePrompt(player, shift)` utility — pulls trait fields, computes effective_age with clamp, omits blank optional fields.

3. `POST /api/players/[id]/avatar/upload` — accept multipart `avatar` field, validate type (PNG/JPG) + size (≤5MB), upload to same R2 key, upsert `player_avatars` with `base_source='uploaded'`, return `{ url }`.

Gate: `npm run check`; smoke test generate-base in dev server console; confirm R2 key appears in bucket.

### Task 4 — Backend: themed-batch endpoint

File: `ui/src/routes/api/avatars/generate-themed/+server.ts`

1. `POST /api/avatars/generate-themed { roundId }` — fetch round (title, description), fetch all players with `avatar_gender IS NOT NULL`.
2. Fan out via `Promise.allSettled` (not `Promise.all`) — per-player failures isolated. For each settled player: on success upload `{playerId}/themed.png` + upsert; on failure log + continue.
3. Return `{ generated: N, failed: M }`.

Gate: `npm run check`; invoke with a real round ID in dev; verify result counts match player count.
