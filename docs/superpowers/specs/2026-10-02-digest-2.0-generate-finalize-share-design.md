# Digest 2.0 — Generate → Finalize → Share (season-ready) — design spec

**Date:** 2026-10-02 · **Status:** design approved in chat 2026-10-02, spec pending review
**Deadline:** usable before round 1 of the next season closes (~2026-10-09).
**Builds on:** `2026-09-28-digest-2.0-design.md` (Approach A isolation), Phases ①–④b (read-only `/digest2/[roundId]`).

## 1. Goal

From the Content tab, Matt can open a round's 2.0 digest, press **Generate**, review it, press
**Finalize & share**, and get a `https://digest.mattmariani.com/d2/<slug>` link to paste into
WhatsApp. Players must **never** see the admin host (`PUBLIC_APP_BASE_URL`, currently `mlb13…`)
— not in the URL, not in any link, image, or script inside the page.

**Success criteria**
1. Content tab → "2.0 preview" tab → `/digest2/<round>` shows an admin bar with Generate,
   Finalize & share, and (once published) the share link + Copy.
2. Finalize produces a static page at `digest.mattmariani.com/d2/<slug>/` that loads, renders
   every section, has a working Digest/Stats tab switch, and loads all images — and a
   Puppeteer request log of the published copy shows zero requests to the admin host or
   bot-ui (proves zero backend dependency).
3. The published HTML contains no occurrence of the admin host and no root-relative link to an
   app route; publish refuses to write otherwise.
4. Once finalized the page is frozen: it changes only when Matt presses Finalize again, which
   overwrites in place (same slug, same link).
5. The "What's up next" (next-round, red box) section is always the **last** section of the
   digest.
6. The live 1.0 digest, its automation, and its `/d/` artifacts are unaffected.

## 2. Decisions (from brainstorming, 2026-10-02)

| Question | Decision |
|---|---|
| What does Generate do for story sections? | **Reuse the 1.0 generator.** Call the existing `POST /api/digest/<round>/draft` (no body → returns the existing draft, or generates a default one). Editing/regenerating story text stays in the 1.0 editor. |
| Stats in a finalized digest? | **Frozen teaser + Stats tab**, season-to-date as of finalize. Live stats belong to the future player portal (nightly refresh) — out of scope here. |
| Where do the buttons live? | **On the 2.0 page** (admin bar), reached via the existing Content-tab "2.0 preview" tab. Never rendered in the published copy. |
| Publish code | **Forked** from 1.0's `renderDigestHtml` into `lib/digest2/publish.ts`. 1.0's `export.ts` is not edited. |
| Sending | Manual (Matt pastes the link). No auto-send this phase. |

## 3. Components

### 3.1 Section order — next-round last
`routes/digest2/[roundId]/+page.svelte`: move the `NextRoundPreview` block below `ReelSection`
and below `StatsTeaser`, so it is the final element of the Digest view. Encode the order in a
test (render or an ordered-kinds helper) so it can't silently regress.

### 3.2 Share mode for `/digest2/[roundId]`
- `+page.server.ts` returns `share: url.searchParams.get('share') === '1'` in load data —
  the same mechanism 1.0 uses; the root layout already renders the bare (no nav/footer)
  layout when `page.data.share` is true, and because it's load data it survives static serving.
- In share mode the page omits: the admin bar, the "Digest 2.0 (dev) · round N" dev heading
  (replaced by a player-facing title: league name + round name).
- `StatsExplorer` gains an optional `frozen?: boolean` prop (default `false` → no behavior
  change for `/boarz-stats` and other callers). When `frozen`: hide the "← All league stats"
  link (`/stats`), the season-selector form (server round-trip to `basePath`), and "Copy filtered
  link". Client-side tabs and player filters keep working. **Shared component → gitnexus impact
  analysis before editing.**

### 3.3 Admin bar (non-share mode only)
Shown at the top of `/digest2/<round>`:
- **Status line:** "No story draft yet" / "Story draft from <date>" (from the 1.0 active draft),
  and "Published <date> → <link>" when a `digest2_shares` row exists.
- **Generate** → `POST /api/digest/<round>/draft` (existing endpoint, empty body). Shows a busy
  state (LLM generation can take minutes); on success reloads the page data
  (`invalidateAll`). Shown only when the round has no 1.0 draft (the round-end automation
  usually creates one first); to regenerate an existing story, use the 1.0 editor link.
- **Edit story in 1.0 editor** → link to `/digest/<round>`.
- **Finalize & share** (enabled once a story draft exists) → `POST /api/digest2/<round>/publish`.
  On success shows the returned URL with a **Copy** button. When already published, label is
  "Re-publish" and a confirm notes that the existing link's content will be replaced.

### 3.4 Publish endpoint + renderer
`routes/api/digest2/[roundId]/publish/+server.ts` → `publishDigest2(roundId)` in
`lib/digest2/publish.ts`:
1. Validate round id (400 bad / 404 unknown). Require a 1.0 active draft (409 otherwise).
2. `getOrCreateDigest2Slug(roundId)` — reuse row in `digest2_shares`; else mint 16 random bytes
   base64url (same entropy as 1.0) and insert.
3. Puppeteer loads `${APP_INTERNAL_URL}/digest2/<round>?share=1`, capturing the same-origin
   `/_app/` asset closure (as 1.0 does), plus any same-origin image under `/share/` (player
   cards) and other same-origin static assets the page requests.
4. Transform the captured HTML (forked from 1.0's `transformShareHtml`): `../_app/`→`./_app/`;
   strip icon/manifest links; localize Google Fonts; add the fetch guard for `/api/ml-auth`;
   rewrite captured same-origin asset URLs (e.g. `/share/x.jpg`) to `./share/x.jpg`.
5. **Leak scan (hard gate):** reject if the output (HTML + captured JS/CSS text) contains the
   admin host from `appBaseUrl()`, or the HTML contains a root-relative `href`/`src`/`action`
   to anything other than captured, rewritten assets. Error lists the first offending snippets;
   **nothing is written** on failure.
6. Write atomically: render into `digests/d2/.<slug>.tmp/`, then swap into `digests/d2/<slug>/`
   (a failed re-publish leaves the previous good copy live).
7. Update `digest2_shares.updated_at`; return `{ slug, url: \`${digestBaseUrl()}/d2/${slug}\` }`.

Only writes: `digest2_shares` and `digests/d2/`. No 1.0 table, no `/d/`, no `/_media/` writes.

### 3.5 Digest host
`Caddyfile.digest`: add a `handle /d2/*` block identical to `/d/*`
(`Cache-Control: public, max-age=300`, `file_server`), placed before the `@league` matcher.
Update the header comment's namespace list. The `/api/p/*` proxy is untouched. Reload/recreate
the digest-static container.

## 4. Error handling
- Generate failure → admin bar shows the endpoint's error text; page stays usable.
- Publish failure (Chromium, leak scan, disk) → error shown with detail; previous published copy
  (if any) remains live thanks to the atomic swap.
- Unknown/non-integer round on any 2.0 route → 404/400, never 500.

## 5. Testing
- **Unit (vitest):** leak scan (admin host in HTML → reject; in a JS chunk → reject; root-relative
  app href → reject; clean fixture → pass — fixtures where right and wrong answers differ);
  HTML transform (asset rewrites, font localization, fetch guard); slug reuse (second call returns
  the same slug); publish endpoint 400/404/409; share-mode load data; `StatsExplorer` frozen hides
  the three server-bound controls and default renders them; next-round is the last digest section.
- **Integration (manual, against a DB copy):** publish round 152 into a scratch `DIGESTS_DIR`;
  serve that dir with a plain static server on another port, open with the app stopped/unreachable,
  confirm sections, stats tab, images, no network calls to the admin host (Puppeteer request log).
- **Post-deploy smoke:** Finalize a real round, fetch `digest.mattmariani.com/d2/<slug>/` → 200,
  grep body for admin host → none, check the Stats tab and images in a browser.
- Repo gates: `npm run check` clean, gitnexus impact before editing shared symbols
  (`StatsExplorer`, root layout if touched), detect-changes before commits, bundle grep after deploy.

## 6. Out of scope
Auto-send to WhatsApp; the section builder / one-off library; listing 2.0 digests in the b-side
league archive; the player portal (live nightly stats + theme surveys — its own design, and any
survey write API is a separate security decision for the Access-less digest host); a forked 2.0
LLM generator; per-league v1/v2 switch.
